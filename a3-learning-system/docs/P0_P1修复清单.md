## P0 — 致命级（直接影响晋级，不修复大概率省三）

### P0-1 知识库无教材内容

**官网依据**："参赛团队需自行构造至少一门完整高校专业课程的初始知识库"

**现状**：RAG架构完整（Dense+BM25→RRF→CrossEncoder），ChromaDB集合已创建，但知识库中无教材数据。所有资源生成都是纯LLM输出，无课程知识约束。

**影响**：硬性要求，不满足直接判为功能缺失。资源生成质量无法保证（无教材参考→LLM自由发挥→可能产生事实错误）。

**修复方案**：
1. 选取一门课程教材（建议"Python程序设计"或"数据结构"，与已有KG匹配）
2. 将教材按章节切分为chunks（500-1000字/chunk，保留上下文重叠）
3. 通过 `/api/admin/upload` 上传，自动向量化→入库ChromaDB+FAISS
4. 同时在 `docs/` 目录下放置对应 `kg_*.json` 知识图谱文件
5. 验证：RAG Center页面执行查询，确认稠密+稀疏+精排全链路返回教材内容

**预期提分**：功能实现 +8，创新 +2

### P0-4 多智能体架构不是真正的"协同"

**官网依据**："体现多智能体架构设计，不同角色智能体协作完成"

**现状**：Supervisor串行路由到单个Worker Agent。Agent之间无直接通信、无并行执行、无结果交叉验证。`supervisor.py:333-462` 证明所有Worker执行完后都回到Supervisor，Supervisor再决定下一个或END。

**影响**：这是功能实现(45%)中的核心评审点。评委看到的是带路由的prompt chain，不是多智能体协同。14届一等奖作品是真正的多Agent并行协作架构。

**修复方案**（选择1-2个实施）：
1. **并行出题+答案交叉验证**（最易实现）
   - Question Agent出题 ↔ Evaluation Agent同时验证题目质量
   - 两个Agent通过state.agent_outputs交换数据
   - 在supervisor中添加并行节点：`workflow.add_node("parallel_qa", [question_agent, evaluation_agent])`

2. **资源生成+质量审核并行**（中等难度）
   - Resource Agent生成内容 → 同时触发Profile Agent审核是否符合画像
   - 审核结果反馈到输出

3. **路径规划+资源预生成协同**（较高难度）
   - Path Agent规划路径 → 同时触发Resource Agent预生成下一节点资源
   - 减少用户等待时间

**预期提分**：功能实现 +3~5

### P0-5 学习路径不是"动态的"

**官网依据**："规划科学、动态的个性化学习路径"

**现状**：`path_agent.py:362 _teaching_init` 一次性生成路径。之后BKT更新→学生掌握状态变化→路径不重规划。这不是"动态"路径，是静态路径。

**影响**：功能实现(45%)评审点。评委要求的是"随学随调"的路径。

**修复方案**：
1. 在 `_post_agent_event_hook`（`chat.py:208`）中，resource_agent完成教学后检测BKT状态变化
2. 如果新掌握的节点改变了拓扑排序（前置依赖满足→新节点解锁），自动调用path_agent重规划
3. SSE推送 `event: path_update` 事件通知前端
4. 前端LearningPathView监听该事件，刷新DAG图

**预期提分**：功能实现 +3~4

## P1 — 高危级（影响省一冲国赛）

### P1-1 画像6维中3维有水份

**官网依据**："多维度精准评估"

**现状及问题**：

| 维度 | 当前计算方式 | 问题 |
|------|------|------|
| focus | `evaluation_agent.py:179-181` — 自报weekly_hours/30*100 | 学生虚报无从验证 |
| logic | `evaluation_agent.py:183-186` — accuracy_rate×0.5+mastered_rate×0.5 | 与knowledge高度共线 |
| practice | `evaluation_agent.py:164-174` — 无答题记录时默认50 | 无数据时给中性分误导 |

**修复方案**：
1. focus → 改用活跃天数+会话频率+日均学习时长（从conversation/answer_record表统计）
2. logic → 改用BKT变异系数（低方差=均衡=逻辑强）+ 跨概念迁移能力（在未学过的相关概念上的表现）
3. practice → 无答题记录时应为0（诚实），而非50（误导）

**预期提分**：创新 +2

**现状**：`bkt_service.py:1149-1172` 的 `_load_kg_vocabulary()` 从 `docs/kg_*.json` 静态加载，运行时不更新。用户通过RAG Center上传新教材后，概念名规范化仍用旧的静态词汇表。
