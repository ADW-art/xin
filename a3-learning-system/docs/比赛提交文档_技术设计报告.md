## 一、需求分析

### 1.1 当代大学生学习痛点

通过对高校学习场景的深入调研，我们识别出以下核心痛点：

| 痛点 | 现状 | 后果 |
|------|------|------|
| **一刀切教学** | 所有学生面对相同的教材、相同的进度、相同的难度 | 基础好的学生浪费时间，基础差的学生跟不上 |
| **资源不匹配** | 搜索引擎给出的资料与个人知识水平脱节 | 找到的资料要么太浅（已经会了），要么太深（看不懂） |
| **缺乏科学评估** | 学生不知道自己真正掌握到什么程度 | 盲目刷题，不知道薄弱环节在哪 |
| **被动学习** | 不知道下一步该学什么 | 学习路径碎片化，知识点间的前置依赖关系被忽略 |
| **遗忘无提醒** | 学过的知识点长期不复习就忘了 | 没有系统化的复习计划 |

### 1.2 大模型与AI技术的解决方案

本项目通过以下技术组合，系统性地解决上述痛点：

| 技术 | 解决的痛点 | 实现方式 |
|------|-----------|---------|
| **多智能体协同** | 一刀切教学 | 7个角色Agent各司其职，根据学生画像个性化服务 |
| **BKT贝叶斯知识追踪** | 缺乏科学评估 | 四参数概率模型，从答题数据中推算真实掌握度 |
| **知识图谱+拓扑排序** | 被动学习 | 基于前置依赖关系规划科学学习路径 |
| **混合检索RAG** | 资源不匹配 | Dense+BM25→RRF→CrossEncoder，从教材库中精准检索 |
| **艾宾浩斯遗忘曲线** | 遗忘无提醒 | 间隔递增复习法，自动跟踪每个知识点的遗忘风险 |
| **大模型个性化生成** | 所有痛点 | 讯飞星火API驱动，根据画像+BKT+RAG生成定制内容 |

### 1.3 功能需求矩阵

| 编号 | 功能 | 类型 | 描述 |
|------|------|:--:|------|
| F1 | 对话式学习画像构建 | 必做 | ≥6维度，自然语言采集，动态更新 |
| F2 | 个性化资源生成 | 必做 | 13种资源类型，多Agent协作 |
| F3 | 学习路径规划与推送 | 必做 | 知识图谱拓扑排序，动态调整 |
| F4 | 智能辅导 | 加分 | TTS语音合成，Mermaid图解说明 |
| F5 | 学习效果评估 | 加分 | 6维量化评估，BKT知识追踪驱动 |

## 三、核心算法设计

### 3.1 BKT 贝叶斯知识追踪

**理论基础**：Corbett & Anderson (1995) "Knowledge Tracing: Modeling the Acquisition of Procedural Knowledge"

**四参数概率模型**：

| 参数 | 符号 | 默认值 | 含义 |
|------|------|:--:|------|
| 初始掌握概率 | P(L₀) | 0.30 | 学生在未学习时已掌握的概率 |
| 学习转移概率 | P(T) | 0.20 | 每次答题后从未掌握到掌握的概率 |
| 猜测概率 | P(G) | 0.15 | 未掌握但猜对的概率 |
| 失误概率 | P(S) | 0.10 | 已掌握但答错的概率 |

**贝叶斯更新公式**（代码位置：`bkt_service.py:237-256`）：

```
答对: P(known|c) = P(known)×(1-P(S)) / [P(known)×(1-P(S)) + (1-P(known))×P(G)]
答错: P(known|w) = P(known)×P(S) / [P(known)×P(S) + (1-P(known))×(1-P(G))]

学习转移: P(L_{t+1}) = P(L_t|obs) + (1 - P(L_t|obs)) × P(T)

最终: clamp(P(final), 0.01, 0.99)
```

**掌握度判定**：

| P(known) | 等级 | 含义 |
|------|------|------|
| ≥ 0.85 | 精通 | 可以跳过，推荐进阶 |
| 0.60 ~ 0.85 | 熟悉 | 可挑战较难题 |
| 0.35 ~ 0.60 | 学习中 | 需继续练习 |
| < 0.35 | 入门/薄弱 | 需重点加强 |

**EM参数拟合**（`bkt_service.py:528-703`）：坐标下降+6组随机种子初始化+黄金分割搜索，自动为每个知识点学习个性化的P(T)/P(G)/P(S)参数。

**测试验证**（`test_bkt_v4.py:100-112`）：手算验证贝叶斯公式——`numerator = 0.3×(1-0.1) = 0.27`, `denominator = 0.27+0.105 = 0.375`, `posterior = 0.72`。

### 3.2 混合检索 RAG 流水线

**四级流水线架构**（代码位置：`rag_service.py:291-356`）：

```
查询文本 "Python装饰器的使用场景"
    │
    ├── 阶段1: Dense召回 (BGE-M3 dense embedding + FAISS)
    │    └── Top-30 稠密向量候选
    │
    ├── 阶段2: BM25稀疏召回 (jieba分词 + BM25Okapi)
    │    └── Top-30 稀疏关键词候选
    │
    ├── 阶段3: RRF融合 (Reciprocal Rank Fusion, k=60)
    │    └── score(doc) = Σ 1/(60 + rank_i + 1)
    │    └── Top-15 融合候选
    │
    └── 阶段4: CrossEncoder精排 (BGE-Reranker-v2-m3)
         └── 逐对评分 [query, doc_content[:512]]
         └── Top-K 最终结果
```

**降级策略**：FAISS不可用→降级ChromaDB；BGE未加载→跳过RAG用Content Store；Content Store不可用→纯LLM生成并标记`rag_degraded`。

**RAG追踪可视化**：`rag_trace()` 返回四阶段完整中间结果，含每阶段耗时和评分统计，前端RagCenter实时展示。

### 3.3 知识图谱+拓扑排序

**多学科KG**：10个学科领域（Python/C++/Java/Go/前端/ML/算法/网络/数据库/OS），每个领域独立的`kg_*.json`文件，按需加载。

**KG结构**：
```json
{
  "nodes": [{"name": "变量", "keywords": ["赋值", "类型"]}, ...],
  "edges": [{"source": "变量", "target": "列表"}, ...]
}
```

**拓扑排序**（`knowledge_graph.py`）：Kahn算法，基于入度的DAG排序。已知(已掌握)节点视为"已完成"，从图中移除后重新计算入度，生成去重拓扑序列。

**教学路径构建**（`path_agent.py:362-399`）：
1. 加载对应学科KG
2. BKT获取已掌握节点→known集合
3. 拓扑排序→阶段划分（每阶段3-5个节点）
4. 时间估算（每节点3h × weekly_hours = 日历周数）
5. 动态重规划：BKT变化后自动重跑拓扑（`replan_remaining_path`）

### 3.4 艾宾浩斯复习调度

**遗忘公式**：R = e^(-t/S)，其中R=记忆保留率，t=距上次学习天数，S=记忆强度

**间隔递增序列**：[1天, 3天, 7天, 14天, 30天, 90天]

**记忆强度演化**：初始S=4.0（≈1天后78%保留率），每次复习+1.5，上限20.0

**风险判定**：R<0.5→高风险(立即复习)，R<0.7→中风险(建议复习)，R≥0.7→安全

## 四、多智能体系统设计

### 4.1 整体架构

基于LangGraph框架构建，采用Supervisor-Worker模式+并行协同增强：

```
                    ┌─────────────┐
                    │  Supervisor │  (规则优先+LLM兜底的路由器)
                    └──┬──┬──┬──┬─┘
          ┌───────────┘  │  │  │  └───────────┐
          ▼              ▼  ▼  ▼              ▼
   ┌──────────┐  ┌──────────────────┐  ┌──────────────┐
   │ Profile  │  │ 协同节点              │  │   Chat       │
   │ Agent    │  │ QA ∥ Eval (并行)     │  │   Agent      │
   │(画像采集)│  │ Resource + QC (串行) │  │  (闲聊处理)   │
   └──────────┘  │ Path ∥ Prefetch     │  └──────────────┘
                 └──────────────────┘
```

**LangGraph图结构**（`supervisor.py:1185-1250`）：11个节点（supervisor + chat_agent + 5个Worker Agent + 3个协同Join节点 + prefetch_agent），Supervisor条件路由到7个Worker+3个协同节点，所有Worker→Supervisor保留闭环。

**状态管理**（`state.py:75-111`）：Pydantic BaseModel，10个字段，含4种自定义Reducer（add_messages/last_value/concat_str/merge_dict/teaching_context），支持消息历史自动合并和并行节点安全写入。

### 4.2 各Agent详细设计

#### Supervisor — 调度中枢

- **路由策略**：60+中文关键词四级优先级→LLM星火API兜底分类
- **意图分类**：6种意图（chat/resource/question/path/evaluation/profile）
- **教学流程管理**：自动推进（阶段内3节点连续）、阶段边界暂停、BKT闭环检测
- **画像优先机制**：<3维时自动路由到profile_agent，延迟原始意图

#### Chat Agent — 闲聊处理

- **职责**：处理问候、感谢、道别等非学习意图的日常对话
- **触发条件**：Supervisor意图分类为chat时路由到此节点
- **风格**：友好、简洁，引导用户转向学习话题
- **图位置**：直接连接到END，不返回Supervisor（`chat_agent → END`）

#### Profile Agent — 画像采集

- **6维画像**：knowledge_base(知识基础) / cognitive_style(认知风格) / learning_goal(学习目标) / weekly_hours(时间投入) / error_patterns(易错模式) / preferred_resource_type(偏好资源)
- **渐进式采集**：每轮对话1-2维度，不一次全问
- **LLM输出解析**：正则+JSON提取，KB_BLACKLIST过滤13个泛化回复
- **BKT同步**：sigmoid映射将profile自评分数转为BKT先验P(L₀)

#### Resource Agent — 资源生成

- **13种资源类型**：document(知识文档) / mindmap(思维导图) / question_set(练习题集) / code_example(代码案例) / video_script(视频脚本) / diagram(图解) / reading_material(阅读材料) / smart_tutoring(智能辅导) / comparison(对比分析) / notebook(交互笔记) / audio_lecture(音频讲解) / video_animation(视频动画) / visual_diagram(视觉图示)
- **反幻觉铁律**（9条强制规则）：禁止猜测代码输出、禁止行尾注释猜返回值、每个代码块后必须紧跟运行结果、至少3个代码块
- **6部分强制结构**：概述→核心概念→代码实战→常见陷阱→练习→下一步
- **RAG知识注入**：三级降级（BGE→Content Store→纯LLM）
- **画像个性化**：根据cognitive_style调整内容风格（视觉型多图表、动手型多代码）

#### Question Agent — 自适应出题

- **双模式**：出题模式（BKT自适应难度）+ 评阅模式（自动批改+BKT更新）
- **3种题型**：概念选择（4选项）、代码阅读（追踪输出）、代码编写（函数签名+约束）
- **难度自适应**：连续对2→升难度，错1→降难度
- **答案缓存**：24h TTL LRU，从对话历史恢复兜底

#### Path Agent — 路径规划+教学引擎

- **双模式**：规划模式（完整DAG阶段计划）+ 教学模式（逐节点推进）
- **拓扑排序**：Kahn算法，基于BKT掌握状态跳过已掌握节点
- **动态重规划**：BKT变化后自动重跑拓扑（`replan_remaining_path`），新解锁节点立即插入路径
- **阶段管理**：3节点/阶段，阶段边界暂停给用户选择（继续/练习/复习）

#### Evaluation Agent — 效果评估

- **6维量化评估**：knowledge(知识掌握) / speed(学习速度) / practice(实践能力) / focus(投入度) / logic(逻辑思维) / trend(学习趋势)
- **数据来源**：全部基于真实行为数据（BKT/bkt_states/conversation/answer_records），不依赖LLM评分
- **Mermaid图表**：后端自动生成知识分布饼图，不受LLM生成质量影响

### 4.3 并行协同架构

**协同节点1 — QA协同**（`collaboration.py:34-107`）：
```
Question Agent ∥ Evaluation Agent
    出题(BKT自适应)      审题(难度匹配/薄弱覆盖)
         ↓                    ↓
    合并输出: 题目 + _review(score/notes)
```

**协同节点2 — 资源协同**（`collaboration.py:168-191`）：
```
Resource Agent → Quality Reviewer (串行后处理)
    生成内容(RAG注入)     →     质检(BKT匹配/风格适配/结构检查)
                                     ↓
合并输出: 资源 + _quality(score/issues/difficulty)
```

**协同节点3 — 路径协同**（`collaboration.py:194-215`）：
```
Path Agent ∥ Prefetch Agent
    规划路径(拓扑排序)     预生成首节点资源
         ↓                    ↓
    合并输出: 路径 + _prefetched_resource
```

**容错设计**：每个协同节点30s超时，单个Agent失败时自动回退串行，主输出不受影响。

所有数据展示页面均实现loading/error/empty/data四种状态：
- **Loading**：骨架屏/旋转器
- **Error**：错误图标+消息+重试按钮
- **Empty**：自定义SVG插图+引导文案+CTA按钮
- **Data**：实际内容渲染

### 6.4 SSE流式对话

- 手动fetch+ReadableStream解析
- 事件类型（12种）：message / agent_switch / progress / collaboration / path_update / done / error / suggestion / prefetch / review_due / system_notice / resource_ready
- AbortController支持用户中止生成
- 800ms发送冷却防重复（`SEND_COOLDOWN = 800`）
