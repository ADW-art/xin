# 多智能体协作系统重构方案

> 对标：LangGraph 2025 最佳实践 + LangChain Supervisor Pattern + HITL
> 当前 Agent 系统：6 Agent + Supervisor 路由，LangGraph StateGraph 编排
> 重构目标：省一答辩可展示的技术深度 + 生产级可维护性

---

## 一、当前架构问题诊断

### 1.1 架构层面

| 问题 | 位置 | 严重度 |
|------|------|:--:|
| Supervisor 承担双重职责：路由 + 直接回复 | `supervisor.py` chat 分支 | 高 |
| 无 Agent 注册表，新增 Agent 需改 4 处代码 | `__init__.py` 为空 | 高 |
| Agent 间无直接通信（handoff），全经 Supervisor 串行 | 全部 Agent → Supervisor → 下一个 | 中 |
| Worker 输出经 Supervisor 二次生成（bridge），延迟高且可能失真 | `chat.py:_bridge_stream` | 中 |
| 无 LangGraph Command 模式，直接修改 state 字段 | 各 Agent 返回 dict diff | 低 |

### 1.2 代码层面

| 问题 | 位置 | 严重度 |
|------|------|:--:|
| AgentState 无 error/retry 字段 | `state.py` | 高 |

| Evaluation Agent 硬编码幻数 | `evaluation_agent.py` | 中 |
| Question Agent 模块级缓存无 TTL | `question_agent.py` | 中 |

### 1.3 前端层面

| 问题 | 位置 | 严重度 |
|------|------|:--:|
| AgentCenter 轮询 chatStore 而非消费结构化 trace | `AgentCenter.vue` | 高 |
| Token 统计始终为 0 | `stats.totalTokens += 0` | 中 |
| 无 Agent 执行耗时/调用链可视化 | 全部 | 中 |

## 二、重构目标架构

### 2.1 架构对比

```
【当前】                              【重构后】

User → chat.py SSE                    User → chat.py SSE
  │                                      │
  ├─ _extract_and_boost                 ├─ _extract_and_boost (KG-based)
  ├─ _silent_profile_collect           ├─ _silent_profile_collect (intent-filtered)
  └─ _bridge_stream:                   └─ graph.astream():
       graph.astream()                       │
         │                              ┌────┴────────────────────┐
         ├─ supervisor_node             │  AgentRegistry           │
         │   ├─ intent classify          │  ├─ chat_agent (新增)    │
         │   ├─ chat reply (直接回复!)    │  ├─ profile_agent        │
         │   └─ route → worker           │  ├─ resource_agent       │
         ├─ worker_node                  │  ├─ question_agent       │
         │   └─ 返回 dict diff           │  ├─ path_agent           │
         └─ back to supervisor           │  └─ evaluation_agent     │
           └─ bridge 二次生成 worker 输出  └────────────────────────┘
                                              │
                                         Command-based handoff
                                         Worker → END (直出, 无二次生成)
                                         AgentTrace API → 前端实时追踪
```

### 2.2 核心改进

1. **Agent Registry 模式** — 集中注册，插件化扩展
2. **Chat Agent 独立** — Supervisor 只做路由，回复交给 chat_agent
3. **Worker-as-Terminal** — Worker 完成直接返回用户，不经 Supervisor 二次生成
4. **Command-based Handoff** — 使用 LangGraph Command 对象替代手动 state 修改
5. **AgentTrace API** — 结构化追踪数据，前端消费实时调用链
6. **Typed State** — AgentState 增加 error/retry/trace 字段，用 Pydantic 验证

## 三、Agent Registry（插件化注册中心）

### 3.1 设计

```python
# backend/app/agents/registry.py (新增)

from dataclasses import dataclass, field
from typing import Callable, Optional
from langgraph.graph import StateGraph, END

@dataclass
class AgentDefinition:
    """Agent 注册定义"""
    name: str                          # "profile_agent"
    display_name: str                  # "画像采集 Agent"
    description: str                   # "通过对话式交互构建6维学生画像"
    icon: str                          # "UserFilled" (Element Plus 图标名)
    node_fn: Callable                  # 图节点函数
    keywords: list[str] = field(default_factory=list)  # 意图分类关键词
    priority: int = 0                  # 路由优先级
    terminal: bool = False             # True = Worker 完成后直出, 不回到 Supervisor

class AgentRegistry:
    """多智能体注册中心 — 单例"""
    _agents: dict[str, AgentDefinition] = {}

    @classmethod
    def register(cls, defn: AgentDefinition):
        cls._agents[defn.name] = defn

    @classmethod
    def get_all(cls) -> list[AgentDefinition]:
        return list(cls._agents.values())

    @classmethod
    def build_graph(cls, state_cls, checkpointer) -> StateGraph:
        """从注册表自动构建 StateGraph"""
        workflow = StateGraph(state_cls)
        for agent in cls._agents.values():
            workflow.add_node(agent.name, agent.node_fn)
        # Supervisor 路由
        workflow.add_conditional_edges(
            "supervisor",
            cls._router_fn,
            {a.name: a.name for a in cls._agents.values()} | {"END": END}
        )
        # Terminal agents → END, non-terminal → supervisor
        for agent in cls._agents.values():
            if agent.name == "supervisor":
                continue
            target = END if agent.terminal else "supervisor"
            workflow.add_edge(agent.name, target)
        workflow.set_entry_point("supervisor")
        return workflow.compile(checkpointer=checkpointer)
```

### 3.2 使用方式

## 四、AgentState 增强（Pydantic 验证 + 追踪）

```python
# backend/app/agents/state.py (重构)

from pydantic import BaseModel, Field
from typing import Optional, Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import BaseMessage
import time

class TraceEntry(BaseModel):
    """单次 Agent 执行追踪"""
    agent: str
    start_ms: float
    end_ms: float = 0
    input_tokens: int = 0
    output_tokens: int = 0
    intent: Optional[str] = None
    error: Optional[str] = None

class AgentState(BaseModel):
    """多智能体共享状态 (Pydantic v2)"""
    messages: Annotated[list[BaseMessage], add_messages] = Field(default_factory=list)
    current_agent: str = "supervisor"
    next_agent: Optional[str] = None
    user_profile: Optional[dict] = None
    context: dict = Field(default_factory=dict)
    agent_outputs: dict = Field(default_factory=dict)
    stream_buffer: str = ""
    user_id: int = 0

    # ── 新增字段 ──
    trace: list[TraceEntry] = Field(default_factory=list)   # 执行追踪链
    error: Optional[str] = None                               # 错误信息
    retry_count: int = 0                                      # 重试计数
    parent_agent: Optional[str] = None                        # 发起调用的 Agent
```

## 五、Worker-as-Terminal 模式（防二次生成失真）

### 5.1 当前问题

```
User 问 → Supervisor 路由 → Worker 生成资源
  → 结果回到 Supervisor → Supervisor 用 LLM 二次总结 → User 看到
```
这导致：(1) 延迟翻倍 (2) Worker 的精确输出被 LLM 改写失真 (3) token 浪费

### 5.2 重构方案

```
User 问 → Supervisor 路由 → Worker 生成资源 → 直接 END → User 看到
```

Worker 节点返回 `Command(goto=END, update={"stream_buffer": worker_output})`。
SSE 直接流式推送 Worker 的 `on_chat_model_stream` 事件，不经 Supervisor 中转。

```python
# 各 Agent 节点改为:
from langgraph.types import Command

def profile_agent_node(state: AgentState) -> Command:
    result = _do_profile_work(state)
    return Command(
        goto=END,
        update={
            "stream_buffer": result["output"],
            "current_agent": "profile_agent",
            "trace": state.trace + [trace_entry],
        }
    )
```

### 6.1 后端 API

```python
# backend/app/api/agent_trace.py (新增)

@router.get("/api/agent-trace/{thread_id}")
def get_trace(thread_id: str) -> TraceResponse:
    """返回某次对话的 Agent 调用链"""
    state = graph.get_state(config={"thread_id": thread_id})
    return TraceResponse(
        agents_used=[t.agent for t in state.trace],
        total_tokens=sum(t.input_tokens + t.output_tokens for t in state.trace),
        total_time_ms=sum(t.end_ms - t.start_ms for t in state.trace),
        call_chain=_build_chain(state.trace),
    )
```

## 九、关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 状态验证 | Pydantic BaseModel | 替代 TypedDict，运行时类型强制 |
| Agent 注册 | Registry 单例 | 集中管理，插件化扩展 |
| Worker 输出 | Command(goto=END) | 防二次生成失真，降低延迟 |
| 前端追踪 | REST API (/agent-trace) | 简单可靠，无需 WebSocket |
| 错误处理 | state.error + state.retry_count | 支持指数退避重试 |
| 长期记忆 | LangGraph Store | 跨会话持久化用户偏好 |
