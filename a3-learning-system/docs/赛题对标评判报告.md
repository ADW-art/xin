# A3 赛题对标评判报告

> 对照标准：第十五届中国软件杯 A3 赛道官网赛题要求
> 赛题：基于大模型的个性化资源生成与学习多智能体系统开发
> 出题方：科大讯飞 | 评分权重：功能45% + 创新35% + 文档10% + 演示10%

---

## 一、必做功能逐条评判

### 必做1：对话式学习画像自主构建

**官网要求原文**：通过自然语言对话自动抽取学生特征，构建不少于6个维度的动态学生画像（如知识基础、认知风格、易错点偏好等），支持"随学随新"。

**项目实际实现**：

| 检查项 | 状态 | 代码依据 | 评判 |
|--------|:--:|------|------|
| 自然语言对话采集 | ✅ | `profile_agent.py:32-372` — Profile Agent通过多轮对话渐进采集 | 达标 |
| ≥6个维度 | ✅ | knowledge_base / cognitive_style / learning_goal / weekly_hours / error_patterns / preferred_resource_type | 达标 |
| 动态更新(随学随新) | ⚠️ | `chat.py:1027` `_silent_profile_collect` 每条消息后静默更新，但绕过Supervisor路由 | 部分达标 |
| 维度计算有数据支撑 | ❌ | `profile_agent.py:92-130` knowledge_score基于话题数量×12+关键字加分，focus_score来自自报数据，非学习行为 | 不达标 |
| 采集完成后有明确引导 | ✅ | `profile_agent.py:133-167` `_build_summary`生成自然语言总结+个性化建议 | 达标 |

**扣分点**：
- 6个维度中knowledge_score是启发式计算（话题数×12+技术关键字+25），非基于实际测试
- focus_score完全来自自报weekly_hours（报30h=100分，报15h=50分），学生虚报无从验证
- `_silent_profile_collect`不经过Supervisor路由，产生"影子更新"——Supervisor不知道profile已变化

**得分**：6/10

### 必做2：多智能体协同的资源生成

**官网要求原文**：体现"多智能体"架构设计，不同角色智能体协作完成至少5种类型的个性化资源生成。

**项目实际实现**：

| 检查项 | 状态 | 代码依据 | 评判 |
|--------|:--:|------|------|
| 多智能体架构 | ⚠️ | `supervisor.py:640-694` — 1个Supervisor+5个Worker的图结构 | 架构存在，但为串行路由 |
| Agent间协作 | ❌ | Worker之间无直接通信，全部经Supervisor串行中转 | 不达标 |
| 5种资源类型 | ✅ | document / mindmap / question_set / video_script / code_example (`resource_agent.py:436-463`) | 达标 |
| 个性化生成 | ✅ | `resource_agent.py:393-400` 根据profile的cognitive_style/goal/preferred_resource_type定制 | 达标 |
| RAG知识注入 | ⚠️ | `resource_agent.py:403-415` — BGE未就绪时静默降级为纯LLM | 部分达标 |
| 反幻觉机制 | ⚠️ | 仅resource_agent有RAG约束+内容检查清单(`resource_agent.py:41-48,145-160`)，其他Agent无 | 部分达标 |

**关键问题：什么叫"多智能体协同"？**

官网原话是"体现多智能体架构设计，不同角色智能体协作完成"。本项目实际是一个Supervisor串行路由到单个Worker的模式：

```
用户 → Supervisor(规则路由) → 单个Agent执行 → 回到Supervisor → END
```

这不是"协作"——Agent之间没有并行执行、没有结果交叉验证、没有协商机制。评委看到的将是一个带路由的prompt chain，而非真正的多智能体协同系统。

**往届优秀作品参照**：第十三届(2024)一等奖华科作品采用了多Agent并行协作架构，Agent之间有显式数据传递和结果交叉验证。

**得分**：5/10（类型数达标，架构不达标）

### 必做3：个性化学习路径规划和资源推送

**官网要求原文**：依托多智能体协同工作机制，规划科学、动态的个性化学习路径，基于画像实现多类型学习资源的精准推送。

**项目实际实现**：

| 检查项 | 状态 | 代码依据 | 评判 |
|--------|:--:|------|------|
| 学习路径规划 | ✅ | `path_agent.py:292-308` — KG拓扑排序+BKT掌握状态→DAG路径 | 达标 |
| 知识图谱支持 | ✅ | `knowledge_graph.py` — 多学科KG JSON加载+拓扑排序 | 达标 |
| 动态调整 | ❌ | 路径在`_teaching_init`(`path_agent.py:362`)一次性生成，后续BKT更新不触发重规划 | 不达标 |
| 资源推送 | ⚠️ | 路径输出概念名列表，通过resource_agent生成对应资源。但路径→资源生成是手动触发而非自动推送 | 部分达标 |
| 融入画像偏好 | ❌ | 路径规划仅依赖BKT p_known，未使用cognitive_style/goal/weekly_hours | 不达标 |

**关键问题：什么叫"动态的个性化学习路径"？**

官网要求"动态"——路径应随学习进展自动调整。本项目路径在初始化后固定不变。学生通过教学掌握了节点A后，后续路径不会重新拓扑排序。这不是动态路径，是静态路径。

**得分**：4/10

## 六、硬伤清单（直接影响晋级）

### 致命伤（不修复大概率省三）

1. **知识库无内容** — 官网明确要求"自行构造至少一门完整高校专业课程的初始知识库"。RAG架构完美但ChromaDB中无教材数据。这是硬性要求，不满足直接判为功能缺失。

2. **比赛文档完全空白** — 需求分析、技术设计、测试报告均不存在。占10%总分，但更关键的是没有文档评委无从了解你的设计思路，连功能分都可能被压低。

3. **演示视频和PPT不存在** — 占10%总分。没有视频评委看不到系统实际运行效果。

### 重伤（影响晋级省一）

4. **多智能体并非真正协同** — 串行路由vs并行协作+交叉验证。评委一眼能看出来。
5. **学习路径非动态** — 官网要求"动态的个性化学习路径"，实际是一次性生成的静态路径。
6. **知识库无内容直接影响资源生成质量** — 所有资源都是纯LLM生成，无教材约束。

### 轻伤（影响国赛级别）

7. 画像维度有水分（focus/logic/practice计算不独立）
8. 无移动端适配
9. 无自动复习推送
10. API/Agent零测试覆盖

## 七、往届对比

### 第十四届(2025) A3一等奖：武汉大学 "面过Mango"

| 维度 | 往届一等 | 本项目 | 差距 |
|------|------|------|:--:|
| 功能完整度 | 7专业领域+10岗位+7场景+3面试官 | 5Agent+5资源类型 | 2档 |
| 多模态 | 语音语调情感+微表情+PDF报告 | TTS朗读+Mermaid图表 | 2档 |
| 文档 | 完整需求+设计+测试+演示 | 0 | 3档 |
| 算法创新 | 情感分析+语言逻辑评估 | BKT+混合检索+KG | **本项目更优** |

### 结论

往届一等奖的功能完整度和交付物远超本项目。但本项目的算法底座（BKT+混合检索）达到甚至超过一等奖水平。关键差距在于：**系统闭环**和**交付物**。
