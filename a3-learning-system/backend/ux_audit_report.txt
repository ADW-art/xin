ROOT CAUSE ANALYSIS (from source code inspection)
======================================================================

ROOT CAUSE #1: Aggressive profile keyword matching breaks learning flow
-------------------------------------------------------------------------
File: app/agents/supervisor.py, lines 239-243 (keyword override):
    profile_kw = ["我是", "我想学", "我有", "我的目标", "初学者", "想找", "求职", "工作"]
    if any(k in last_msg for k in profile_kw):
        intent = "profile"

And in _keyword_fallback(), line 99:
    if any(k in text for k in ["我是", "我想学", "我有", ...]):
        return {"intent": "profile", "params": {}}

PROBLEM: "我想学X" is the MOST COMMON Chinese learning intent expression.
Every "我想学Python数据分析" gets hijacked by profile_agent instead of
resource_agent, because "我想学" matches the profile keyword list.

ROOT CAUSE #2: KB pollution from two separate code paths
----------------------------------------------------------
- _extract_and_boost() in chat.py uses regex to extract concepts from user
  messages for knowledge_base boosting, but has NO blacklist filtering
- profile_agent.py's KB_BLACKLIST (21 entries) only applies during profile
  agent extraction, NOT during chat-level boosting
- Result: "者，之前没学过编程", "8小时", "的知识点" are stored as knowledge points

ROOT CAUSE #3: Non-deterministic LLM intent classification
------------------------------------------------------------
supervisor uses spark.chat_sync() (LLM API) to classify intent. The keyword
fallback was supposed to be the safety net, but it has bugs (see #1).
Evidence: "制定学习计划" correctly routed to path_agent in run 1, but to
profile_agent in run 2. Same input, different results.
