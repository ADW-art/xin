# 阶段闸门规则

## 闸门1：需求确认（confirm）
触发条件：每次代码修改请求
操作：
1. 重述用户需求（一句话）
2. 列出你认为需要改动的文件
3. 列出每个文件改动的预估范围
4. 发现任何不确定的点，必须敲定方案后再继续
5. 提问："理解对吗？"

## 闸门2：方案审批（plan）
触发条件：闸门1 通过，且改动涉及 2 个以上文件或非纯数据逻辑变更

## 闸门3：改后审查（inspect）
触发条件：代码修改完成 + 测试已跑
操作：
1. 展示改动的文件列表和修改摘要
2. 展示测试结果
3. 首尾检查：
   - 项目是否正常运行
   - 修改的代码是否冗余
   - 当前功能状态是否更新
   - 还有什么工作未完成（报告）
   - 临时文件是否清理
4. 提问："验收吗？"

## 紧急通道
[HOTFIX] 可跳过闸门2，但闸门1 和 闸门3 永不跳过。

## 进度报告
工作完成后用 update_plan 或文档记录最新进度。
